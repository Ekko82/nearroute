# 近舟 NearRoute

**为改善 Codex 连接质量而设计的代理节点自动优选工具。**

近舟（NearRoute）运行在 Windows 上，配合你已有的代理客户端，持续检测节点的延迟、探测成功率和波动。当当前线路不健康，或其他节点的表现达到切换条件时，它会自动选择并切换节点，帮助减少代理线路不稳定造成的 Codex 连接失败和重试等待。

支持提供本机 Mihomo/Clash HTTP 控制接口的猫猫云、Clash Verge Rev、Clash Party（原 Mihomo Party）等客户端。近舟会自动发现控制地址和可用代理组；发现多个客户端时，由你选择要管理的连接。

## 它能帮你做什么

- **自动测速与选点**：综合延迟、成功率和波动评估节点，默认日本优先，可按附近地区或自己指定的范围测试。
- **检查当前线路并自动切换**：定期检查连接健康，候选节点复测后验证实际线路，验证失败自动回滚；通过切换门槛、冷却时间和手选保护减少频繁换点。
- **适应你的代理设置**：自动识别本机控制接口，保留手动地址与代理组设置；测试链接、预期状态码和节点范围均可自行修改。
- **在后台运行**：收起到 Windows 系统托盘后继续工作，也支持手动切换、恢复原节点和软件内更新。

自动切换作用于所选代理组的后续新连接，近舟不主动断开已有连接。线路检查与自动切换的具体范围见[作用范围与局限](#作用范围与局限)。

## 快速开始

1. 安装带 tkinter 的 Python 3.10 或更新版本，从[最新正式版本](https://github.com/Ekko82/nearroute/releases/latest)下载 `NearRoute-X.Y.Z-windows.zip`，解压到一个可写的固定目录。安装包使用本机 Python，不附带运行环境。
2. 启动代理客户端并开启本机 HTTP 外部控制。近舟会自动寻找可用接口；需要认证或同时运行多个客户端时，在“客户端连接”中完成设置。
3. 在项目目录打开 PowerShell，运行安装脚本。脚本自动寻找 `pythonw`、`python` 或 `py`，创建桌面快捷方式及当前用户登录启动项。

```powershell
.\install.ps1
```

如果 PowerShell 阻止运行下载的脚本，可以仅对本次进程使用执行策略：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

你也可以指定 Python，或先安装而暂不启动：

```powershell
.\install.ps1 -PythonExe 'C:\Python312\pythonw.exe' -NoStart
.\launch.ps1
```

双击桌面 **近舟 NearRoute** 打开控制窗口。顶部显示当前线路和优选开关，三个状态卡片显示控制接口、可选节点和近期错误；“立即测速”与“恢复原节点”位于节点列表上方。底部的“测速策略”可展开查看当前测试链接和扫描范围。

右上角“客户端连接”设置控制地址、代理组及自动识别开关。“测速设置”分为“节点范围”和“测试目标”两页，可修改扫描范围、日本优先、测试链接和状态码。保存测速设置会保留最新的自动优选开关及其他配置字段；与恢复操作同时发生时，也不会重新开启已关闭的优选。测速期间修改链接或范围后，会取消排队的旧任务，等待在途探测收尾后使用新设置；旧链接结果不会写入新探测历史。首次安装复制的示例配置默认暂停，并使用自适应附近地区；确认连接后，点击“启用优选”。已有 `config.json` 会保留其开关和手动扫描范围。

测速时节点列表保留上轮结果，并逐步更新本轮数据；选中行和滚动位置会保留。双击节点、选中后按 Enter，或右键选择“切换到此节点”，即可手动切换。暂停自动优选时也可操作。手动请求绑定列表显示时的客户端、模式和生效代理组；排队期间模式或代理组改变时，会提示刷新后重试。手动选择默认保持 10 分钟，期间“立即测速”仍可查看排名；若当前线路连续故障，后台可恢复自动选点。

手动切换等待超时后，会尝试撤销尚未处理的请求；迟到返回的请求同样会尝试撤销，避免退出后遗留到下次启动。撤销只针对该次请求，不影响重新选择的节点。已开始的切换可能仍会完成，请以当前节点状态为准。

修改测试链接或预期状态码后，旧目标的成绩和最近测速时间会显示为“—”，保留节点名称并提示等待按当前目标重测。新成绩到达后恢复显示；无法确认测试来源的旧版记录同样等待重测。当前节点和手动切换确认继续正常显示，调整地区范围或日本优先不会清空同一目标的成绩。

切换成功后，健康状态只属于当前线路：自动验证通过时显示本次结果；手动切换未经探测时清除旧线路的健康与验证记录，等待当前线路检查。若最终快照已发现外部换点，也会丢弃前一条线路的检查结果。下一轮普通测速到期时，已识别的新线路若尚无健康结果，后台会先检查当前线路，不沿用旧线路的检查时间延后首次检查；手动“立即测速”和故障恢复仍可优先扫描。

后台刚启动、尚未确认客户端状态时，历史节点也会标为“上次记录”，确认在线后恢复手动操作。后台状态超过两分钟未更新时，界面会标明“上次记录”并显示状态更新时间，保留节点排名供查看。可点击“启用优选”或“立即测速”重新请求服务；旧记录不会被当作仍然在线的连接。

Windows 短暂占用状态文件时，后台会重试更新。持续占用期间后台继续运行，界面保留上次记录，文件可写后恢复更新。后台启动确认独立于状态快照，退出、恢复节点和更新无需等待被占用的状态文件恢复写入；选点和回滚记录写入失败仍会中止相应操作。

空闲时合并内容未变化的状态写入，最长每 15 秒更新一次心跳；测速进度、节点操作及连接恢复状态的变化仍及时保存。

不安装启动项也可以运行：

```powershell
Copy-Item .\config.example.json .\config.json
python -B dashboard.py
```

点击窗口右上角 **×** 会收起到 Windows 右下角系统托盘，已经启用的后台仍会运行。双击托盘图标，或右键选择“打开近舟”，即可恢复窗口；再次双击桌面快捷方式也会唤回已有窗口。Windows 可能把图标放在右下角 **∧** 的隐藏图标区域。

近舟的图标是蓝底白帆，托盘、窗口和桌面快捷方式使用同一标志。托盘按 Windows 显示缩放选择相应尺寸，并在资源管理器重启或缩放改变后重新加载。更新源码后需退出并重新打开窗口；已有桌面快捷方式可重新运行 `install.ps1` 更新图标。

任务栏使用近舟独立的 Windows 应用标识，避免与其他 Python 程序共用图标或分组。已固定的旧任务栏项若仍显示旧图标，可取消固定，再从更新后的近舟窗口重新固定。

托盘右键菜单的“退出近舟（停止优选）”或窗口内的“退出程序”会停止后台优选并退出，保留代理客户端当前节点。退出和更新会等待在途探测收尾，停止等待时间覆盖支持范围内的最长测速请求。下次打开仍沿用原设置。托盘不可用时，× 会最小化到任务栏，避免窗口无法找回。

暂停会取消尚未开始的自动探测、跳过后续复测，并停止自动切换；已在途的节点测速请求正常收尾。线路验证会检查暂停、停止和待处理的手动选点请求，取消不计为线路故障。中断的扫描不计为完整测速，重新启用后会重测。暂停时“立即测速”仍可完成测速，只测量、不切换。暂停期间仍按健康检查间隔读取本机控制器，更新当前节点与连接状态，不发送自动线路探测。控制器离线或后台停止时，界面将旧节点标为“上次记录”。

恢复原节点会停止后台，并只恢复当前选择仍属于本工具、且记录属于当前控制接口的代理组，保留用户后续手动选择。恢复期间不会同时启动新的近舟后台；如果后台已被重新启动，恢复会提示稍后重试。确认恢复成功后会退役该组记录，下次选择重新保存基准节点；无法确认接口归属的旧版记录会保留，但不会自动用于恢复。

## 连接其他客户端

1. 在代理客户端开启本机 HTTP 外部控制，取得实际监听地址、访问密钥（如已开启认证）和 HTTP 或 mixed 代理端口。Clash Verge Rev 的入口见[官方外部控制说明](https://www.clashverge.dev/faq/other.html)；[Clash Party](https://github.com/mihomo-party-org/clash-party) 同样使用 Mihomo。端口以客户端实际配置为准。
2. 打开近舟右上角的“客户端连接”，查看自动发现的接口，也可主动重新发现或填写地址，例如 `http://127.0.0.1:9090`。这是**外部控制端口**，不是 HTTP/SOCKS 代理端口。
3. 无认证时将“密钥环境变量”留空；有认证时填写保存访问密钥的环境变量名，如 `CLASH_SECRET`。这里只保存变量名，不保存密钥。设置变量后须重新启动近舟，例如从同一 PowerShell 窗口启动：

```powershell
$env:CLASH_SECRET = '这里填写客户端的访问密钥'
.\launch.ps1
```

4. 点击“测试连接并读取代理组”，确认当前组或推荐组；有多个可靠候选时自行选择。测试和发现只读取接口，不测速、不切换、不修改订阅。规则模式使用所选组；全局模式实际控制 `GLOBAL`。直连模式可以检查接口，但优选前需回到规则或全局模式。
5. 保存新连接会先停止近舟后台，暂停自动优选并清除旧客户端的界面节点及尚未执行的测速请求，保留已有测速范围与配置。可先点“立即测速”检查，再启用自动优选。指定节点模式的旧名单可能不适用于新客户端，请在“测速设置”重新选择。

开启 `auto_detect_client` 后，后台在控制接口不可用时自动重新发现，重试间隔约 30 秒。发现范围包括常用本机控制端口和已识别 Mihomo/Clash 进程的监听端口，不扫描整个端口范围。当前地址仍可用时继续使用；只有唯一可靠结果才自动更新地址，多个客户端时提示进入“客户端连接”选择。正在验证节点、有未完成恢复事务或待处理的手动选点时，先完成原操作。

开启 `auto_select_group` 后，当前组仍有效时予以保留；组缺失时，依据实际 Codex 连接路径中的组或唯一可直接选择独立节点的 Selector 判断。无法唯一确定时由用户选择，不按代理组名称猜测路由。关闭对应开关即可固定手动地址或代理组。

发现其他地址时不携带当前地址的认证密钥。需要认证的接口会标为待验证，请选择后填写密钥环境变量并测试；只有验证成功的接口才可自动应用。自动识别只调整近舟配置，不关闭已有代理连接。

代理组名称按客户端返回的原文保存，保留开头、结尾的空格，避免选到名称相似的其他组。

目前要求控制接口提供 Mihomo/Clash 的 `/configs`、`/proxies`、节点测速和 Selector 切换 API，并通过本机回环地址的 HTTP 或 mixed 代理端口验证线路。连接地址根据客户端的监听配置自动确定，支持 `127.0.0.1` 和 `::1` 等回环地址；只绑定局域网地址时会提示改用回环或通配监听。[官方 API](https://wiki.metacubex.one/api/) 使用 Bearer 认证。仅有 TUN、SOCKS 或其它管理协议的客户端不能直接接入；v2rayN、sing-box 等不按名称判定兼容，需实际满足上述 API 与代理端口条件。本轮按官方接口适配，并通过隔离控制器测试，未对所有客户端版本逐一实机验证。

不同控制地址、认证环境变量和规则组的记录分别归属；旧节点列表和旧手动请求不会套到新连接。若旧客户端有未完成回滚，保存会提示先恢复原节点。自动处理未完成事务或点击“恢复原节点”时，若本控制器快照已明确证明用户选择了其他线路或原候选变为子组，会结束旧事务并退役其陈旧控制归属，保留当前选择，之后可修改连接；重复恢复也不会依据旧记录重改该线路。自动恢复发现当前生效组被外部选择取代时，会记录默认 10 分钟手选保护，包括用户选回上次观测节点的情况；重新启用或重启均保留同一期限。归属或保护记录写入失败会保留恢复记录供重试。控制器离线、恢复未确认或归属不明时继续保留记录。控制接口禁止跟随 HTTP 重定向，避免转发认证信息。

## 版本与更新

控制窗口底部的“版本与更新”可以查看当前版本、更新说明、立即检查及修改更新偏好。窗口或托盘运行时，默认每 6 小时检查一次 GitHub 的正式 Release；发现新版本会保留界面提示，并请求 Windows 托盘通知。系统通知设置可能影响通知显示。默认只提醒，点击“下载并安装”并确认后才下载、校验和重启近舟。检查失败不打断线路优选，仍可手动重试。

更新偏好还可选择“自动下载，提醒安装”或“空闲时自动安装并重启”。自动下载失败后，会在下一次成功检查版本时允许重试，期间不会连续发起下载。某版本安装失败后会保留提示，停止自动安装该版本；可手动重试，后续新版本仍按更新偏好处理。自动安装会等待测速、候选验证、节点操作和 Codex 连接恢复结束；关闭自动检查也会停止自动下载及安装。只运行后台、没有打开控制窗口或托盘时，不检查应用版本。

后台状态超过两分钟未更新或无法确认时间时，自动安装会等待，收到新的空闲状态后再继续。手动确认后的安装不依赖旧状态记录；若下载期间开始了本地节点操作，会先等操作结束，再停止后台并安装。

“版本与更新”窗口打开时，自动安装会等待，方便阅读说明和修改更新偏好；关闭窗口后再按已保存的偏好处理。窗口内显式点击“安装并重启”仍可立即确认安装。

ZIP 安装更新只接受本仓库正式版本的 HTTPS 安装包，验证大小、SHA-256 和文件清单后安装。安装时停止近舟后台，保留 `config.json`、`state/`、代理客户端和现有启动设置，完成后重新打开近舟；不会再次运行安装脚本或新增启动项。新增的自动识别模块随安装包一并更新，无需另装依赖。替换失败会还原旧版程序，备份保留在 `state/updates/backup`，更新结果会显示在窗口底部。断电或强制终止导致程序无法启动时，可退出近舟后重新解压正式版本包到原目录，保留用户配置和 `state/`。

官方 Git 源码安装也支持“下载并安装”，更新到已发布 Release 对应的标签，并核对源码与正式安装包一致；不会直接跟随 `main`。本地已跟踪文件有改动、分支已领先或分叉、文件覆盖冲突时，窗口内会提示原因并保留本地文件，不自动暂存或重置源码。

仍显示“打开下载页”的旧版源码安装，需要先退出近舟，在原目录执行一次 `git pull --ff-only` 后重新打开，以加载新版更新器。没有更新功能的旧版 ZIP 安装需手动升级一次：退出近舟，将正式版本 ZIP 中的程序文件覆盖到原目录，保留自己的配置和 `state/`；以后通过“版本与更新”安装。不要把 GitHub 自动生成的 Source code ZIP 当作正式更新资产。

## 测试链接和节点范围

默认链接为 `https://chatgpt.com/backend-api/codex/responses`，预期状态码为 `405`：这是 GET 访问 POST 专用端点时的线路检查。HTTP、HTTPS 均支持，程序不跟随重定向，只接受配置中的状态码。推荐响应体较小的健康检查链接，如正常返回 `204` 的接口；响应体上限为 64 KiB，大网页不适合作为空闲连接复用测试的目标。测试链接不应包含登录令牌、密码或其他敏感参数。

四个扫描模式可在界面选择，也可以编辑 `config.json`：

| 模式 | 配置 | 范围 |
| --- | --- | --- |
| 自适应附近地区 | `"scan_mode": "adaptive"` | 每轮按实际节点，选择日本、台湾、新加坡、香港、菲律宾中可用的地区 |
| 地区 | `"scan_mode": "regions"` | 按 `scan_regions` 筛选，默认日本、台湾、新加坡、香港 |
| 指定节点 | `"scan_mode": "nodes"` | 仅扫描 `scan_nodes` 中与控制器节点名完全一致的项目 |
| 全部节点 | `"scan_mode": "all"` | 扫描主代理组下可发现的所有代理叶子节点 |

自适应模式随订阅和代理组节点变化重新判断范围，保留日本优先。没有可识别的附近地区节点时保留当前线路并提示，不自动扩大到其他地区或全部节点。已有地区、指定节点或全部节点配置继续按原范围执行；用户可随时在“测速设置”切换模式。

地区使用两个字母的代码，如 `JP`、`TW`、`SG`、`HK`、`US`；`UNKNOWN` 表示无法识别标签的节点。地区识别依据名称中的文字、代码或旗帜，取最先出现的地点标记，**不代表节点实际地理位置**。一些供应商的台湾节点使用中国旗帜：名称同时有明确台湾或 `TW` 标签时，程序忽略该旗帜并读取文字地点；其他情况下中国旗帜识别为 `CN`。无法识别的名称可以通过指定节点模式精确选入。

指定节点示例：

```json
{
  "scan_mode": "nodes",
  "scan_nodes": ["Japan 01", "Singapore 02"],
  "prefer_japan": true
}
```

`prefer_japan` 控制同一扫描范围内的日本优先策略。当前节点不在扫描范围时，不会被加入候选复测；当前代理路径仍会接受轻量健康检查。更改测试链接或预期状态码后，历史评分与隔离记录会清空，避免混用不同目标的数据。

控制接口、代理组和认证环境变量名称可在“客户端连接”中设置，或在停止后台后编辑 `config.json`。切换接口、认证变量名称或主代理组后，测速历史重新开始，手动保护仅使用对应的选择记录。密钥不需要写入源码或配置文件。控制接口只允许本机地址；请按客户端设置填写实际端口与代理组。全局模式下工具控制 `GLOBAL`，规则模式下控制配置的主代理组。切换候选期间若客户端改变代理模式，近舟会停止本轮切换、回滚尚未提交的选择，并按新模式刷新状态。

## 选择机制

- 默认常规扫描间隔为 5 分钟，最多并发 6 个探测；12 个候选再复测两轮。日本优先开启时，通常为 8 个日本、4 个其他节点，不足时按最快剩余节点补足。扫描范围内的当前节点可额外复测。等待慢速探测时仍会处理手动切换、停止和恢复信号；中止测速时取消尚未开始的探测，已发出的请求正常收尾。
- 完整扫描确认当前节点评分合格、实际路径健康，且仍处于换点冷却期时，下一次普通扫描延至冷却结束，保留上轮节点排名和最近测速时间。每 15 秒的健康检查继续；手动“立即测速”、连续健康失败和 Codex 恢复补测可提前扫描。修改扫描间隔、冷却或选点策略，以及检测到外部节点变化时，会撤销旧的延后安排。
- 使用最近 30 分钟、最多 12 个样本。启动和测速保存时清理过期样本与冷却记录，已删除或更名节点的旧记录会随有效期清理，仍有效的范围外历史会保留。至少 3 个成功样本且成功率不低于 80% 才能候选；评分为 `中位数 + 0.5 × (P90 − 中位数) + 2000 × 失败率`，越低越好。
- 订阅在测速期间移除或重分组节点时，切换前会按当前代理组名单重新确认；已变成子代理组的旧节点也会退出候选，不再用旧评分压制其他地区备用。失效候选会跳过，继续尝试本轮已测的有效备用节点。尚未测速的新节点等待下一轮扫描。
- 默认优先合格日本节点。没有合格日本节点时可选其他节点；日本中位延迟达到 500 ms 时，其他节点评分须不高于日本的 60%；日本已有至少 5 个样本且成功率低于 90% 时，其他节点还须成功率不低于 95%。条件逐个候选判断。
- 有当前有效评分时，普通切换需同时改善至少 60 ms 和 25%，并间隔 30 分钟，以减少健康节点之间的小幅换点。当前节点缺少有效测速样本或不在扫描范围时，也会遵守冷却。日本恢复后从备用地区回切可免改善阈值，仍保留冷却。确定故障时允许绕过冷却；手动更改节点后通常让出 10 分钟，包括在嵌套子组内换点。已检测到的外部手选保护会保存，重启后仅对仍匹配的客户端、实际路径和工具选择记录继续生效。路径变化时，旧线路的检查结果和失败次数不会计入新线路。
- 自动切换前检测到用户已手选其他线路时，会取消本轮切换并保留用户选择；即使用户恰好选中了本轮候选，也不会把这次外部选择误回滚。
- 候选验证结束后，会再次核对它仍是可直接选择的独立节点。验证期间变成子代理组、移出可选名单或实际路径变化时，旧验证结果不再用于提交；回滚与恢复原节点都会核对节点形态，保留新的子组选择。
- 默认每 15 秒检查当前线路；连续两次失败会提前重新扫描。切换候选后检查预期状态码，并在同一连接上完成三次请求，中间各空闲 5 秒。HTTPS 检查同一 TLS 连接，HTTP 检查同一 TCP 连接。定长或分块响应被截断时判为失败。失败会回滚，候选暂时排除 30 分钟，每轮最多尝试 3 个。验证期间暂停会取消验证并回滚临时选择，取消不会隔离候选。
- 每次线路验证请求共用 7 秒网络预算，涵盖 TCP、代理隧道、TLS、响应头和正文；持续缓慢发送的数据不会无限延长等待。两次空闲复用检查的等待不占请求预算。接收数据时检查取消，静默等待最多持续到本次预算结束；超时或取消后关闭这次验证连接。
- 检查与候选验证会复核本机代理监听地址和端口。配置改变时丢弃旧验证，取消未提交的自动切换并恢复临时选点；无可用 HTTP/mixed 端口或仅 LAN 绑定属于客户端配置问题，不累计节点故障或隔离正常候选。暂停时的纯测速仍可进行。
- 候选回滚已确认成功后，会立即结束对应的恢复记录，避免稍后手动选回同名节点时再次被旧记录回滚。控制器离线或恢复未确认时继续保留记录，供后续重试。
- 配置 Codex 日志信号后，每 5 秒检查新产生的 Responses 传输错误，包括请求发送／解码失败，以及 Codex 重试记录中的 TLS 握手提前断开（`tls handshake eof`）、WebSocket 提前关闭和 Windows 连接重置（10054）。最近一次错误后的 60 秒内，暂缓后台测速和普通自动换点，让 Codex 恢复请求；健康检查继续，连续两次线路检查失败仍可故障切换。恢复窗口结束后补测一次，同一批旧错误不会反复触发扫描。手动选点始终可用，“立即测速”仍可测量，健康线路在恢复窗口内不会自动切换。

自动检测和切换需要时间：全量扫描同步执行，探测超时、复测及候选验证都会延长恢复等待。15 秒检查间隔不意味着 15 秒内完成故障切换。

## 作用范围与局限

切换影响同一代理组其他应用的**新连接**。程序不重启内核或关闭已有连接；正在运行的长连接会沿用原来的节点。仅存在于嵌套子组、不能直接由主 Selector 选择的叶子节点，可用于探测但不会被直接切入。

近舟向 Mihomo 提交切换后，会重新读取实际选择并确认结果。猫猫云 5.5.8 没有找到可供外部调用的界面刷新入口，客户端界面的节点名称可能仍来自缓存；近舟的“当前节点”以控制接口返回的实际选择为准。

Mihomo 的测速接口可能只报告耗时，无法保证 HTTP 状态符合预期，因此最终切换还需要当前代理路径验证。HTTPS 会校验证书及主机名，证书失败不会降级为不安全连接。

验证会在同一次请求中读取 `103 Early Hints` 等临时响应之后的最终状态，避免把正常线路误判为失败；HTTP 和 HTTPS 均支持。最终状态不符合预期或响应被截断时仍判为失败，分块响应缺少尾部结束空行也不会被计为成功。

普通 HTTP 测试链接按 Mihomo 的代理连接保持要求复用 TCP 连接，避免单次检查成功却在候选验证时被误判断连；HTTPS 仍在隧道内检查同一 TLS 连接。

这里测量的是 HTTP 线路表现，**不是模型首字延迟，也不能证明任意长度的 SSE 或 WebSocket 均能成功**。服务端推理、限流、服务故障、本机休眠和网络变化仍可能造成断流。后台只发 GET 探测，不发送模型生成请求。

## 连接问题诊断

主界面会持续核对安装文件、当前窗口和后台的运行版本。替换源码后仍运行旧进程时，底部显示版本差异及退出重开提示；活动后台未报告版本时显示“后台版本未知”。过期、其他客户端或已停止后台的快照不会触发后台版本提示。点击 × 只会收起到托盘，请通过“退出程序”正常结束后重新打开，以加载已更新的文件。提示不会自动重启程序或切换节点。

在“版本与更新”中点击“诊断信息”，可以预览并复制本机摘要。它分别显示磁盘上的安装版本、当前窗口已加载的版本、后台已加载的版本及后台启动时间，便于确认更新文件后是否仍在运行旧程序。旧版后台没有版本记录时显示未知；安装版本与已加载版本不同时，按提示正常退出近舟并重新打开。摘要还包含 Python 和系统版本、检查间隔与优选开关、后台状态记录的更新时间、健康及恢复状态，以及本安装最近的选点、回滚和启停时间。

状态已过期、后台处于启停阶段或记录属于旧客户端连接时，相应的当前指标显示为未知。旧版状态缺少归属信息时，归属是否匹配也标为未知，区别于已确认的不匹配。近期事件优先取当前日志，不足 8 条再补前代；它们属于本安装历史，不代表都发生在当前客户端。

报错发生在哪台电脑，就从那台电脑生成摘要。同一代理节点也可能因 Codex 传输配置或本地网络不同而表现不同，其他电脑的日志只能作为对照。摘要中的健康结果仍只代表上述 HTTP 线路检查：预期的 HTTP 405 不代表模型 SSE 或 WebSocket 传输已完整结束。

默认摘要按固定字段整理，只读取近舟的本地文件，不读取 Codex 日志数据库。遇到断流时，可在该窗口显式点击“读取 Codex 断流摘要”，一次性只读查询最近两小时的 Codex 模型传输日志。已填写 `codex_log_db` 时使用该路径；留空时使用 `CODEX_HOME/logs_2.sqlite`，未设置 `CODEX_HOME` 则使用 `~/.codex/logs_2.sqlite`。这次读取不修改配置、不启用后台监测，也不读取 Codex 配置或认证文件。日志信号显示为“已配置”只代表设置了路径，不代表日志数据库可读或正在监测。

每次主动读取都会刷新本次摘要中的近舟版本、状态和事件；重复读取会替换上次结果。断流摘要只提取可信传输记录中的时间、错误类别、重试次数、重试等待时间，以及观测到的 `responses_http` 或 `responses_websocket`；记录数量有上限，读取被截断时会标明。

错误时间对照会从当前及前代近舟事件日志中查找错误前后 120 秒的记录，不受默认摘要最近 8 条事件的限制。对照最多保留最新 256 条事件，超出时单独标明截断。它用于核对时间是否接近，不据此判断断流原因，也不推断请求最终成功。摘要不包含原始日志正文、提示词、令牌、节点名称、控制地址、本机路径、测试链接或密钥环境变量。

两种摘要都不测速、换点、联网、上传或保存新报告。先查看内容，再点击“复制摘要”自行分享。

## 本地记录与隐私

`config.json` 保存本机设置；`state/` 保存节点排名、探测历史、隔离记录、选点和回滚日志、恢复交易及安装备份。它们可能包含节点名称、控制器地址、本机安装路径和时间，因此默认排除在 Git 之外。卸载保留这些数据，分享问题报告前请自行脱敏。

工具无需订阅链接、节点密码或 Codex 登录令牌。默认样例将 `codex_log_db` 留空，关闭 Codex 日志信号；如主动配置该数据库路径，只读识别新产生的 Responses 请求发送失败及传输重试，统计时间与数量，不保存或输出日志正文。前述诊断按钮的一次性读取不改变这项后台设置。探测请求会经过你配置的代理与目标网站，目标及控制器可能记录这些请求。程序没有独立遥测上传功能。

公开仓库只提交源码、测试、样例配置和文档。不要提交或打包 `config.json`、`state/`、个人诊断脚本、订阅或凭据。`.gitignore` 不会移除已经跟踪的文件，发布前应检查实际提交内容。

## 命令与卸载

```powershell
python -B optimizer.py status
python -B optimizer.py scan --dry-run
python -B optimizer.py stop
python -B optimizer.py restore
.\uninstall.ps1
```

后台运行时，`scan` 向它发送一次重新测速请求；独立只测速请先停止后台，再使用 `scan --dry-run`。`--dry-run` 仅用于 `run` 和 `scan`，遇到需要恢复的未完成事务会保留记录并停止测速，提示先显式恢复，不会隐式回滚节点。卸载撤销本工具拥有的当前用户启动项及快捷方式，尝试恢复原节点。控制器离线时可先撤销安装，在线后再运行 `restore`；`uninstall.ps1 -NoRestore` 保留当前节点。

升级时从同一目录重新运行安装脚本。项目与桌面路径支持中文、表情等 Unicode 字符。脚本保持旧 `CodexNodeOptimizer` 启动项名称，避免重复启动；只迁移能证明属于当前项目的旧快捷方式。目录需要迁移时先从原目录卸载，再在新目录安装。

安装中途失败会尝试恢复本次更改前的启动项、快捷方式和安装记录。若快捷方式被占用，可解除占用后重新运行安装脚本。
